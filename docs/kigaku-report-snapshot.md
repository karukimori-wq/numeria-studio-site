# 九星 Report Snapshot

`activeDraft.snapshot` の既存 reading.v1 形式を維持し、任意の `activeDraft.reportSnapshot` を追加する。D1 の既存 active_draft_json に格納し、スキーマ移行は不要。

- 認証済み save-draft がサーバーの実効プランで全14ページを生成する。クライアントの reportSnapshot は採用しない。
- report.v1 に保存日時、対象者名・カルテID、reading（本人・相手・固定日時・計算版・結果）、ページ（原文本文/short/ID/版/出典/承認状態、区間、参照結果、図表データ）を保存する。
- SHA-256 は保存内容の破損検出用。署名や承認の証明ではない。復元時は保存バイトを検証し、現行カタログ・計算版で置き換えない。
- 同じ reading・対象者での再保存やメモだけの保存は元の版と保存日時を維持する。入力編集・再計算では新しい Snapshot を生成する。
- report のない旧v1は従来の再計算照合で復元し、次回保存で report を追加する。他占術・無型の旧下書きは既存経路を維持。
- 有料版を保存後にFreeへ降格すると report を応答から除外する。D1には保持し、再昇格後に元の版を復元する。Freeの基本4ページはreadingから従来のAPIで確認できる。

`POST /api/kigaku/report-print` は保存済み案件IDと standard / magazine を受け取り、保存済み内容からA4草案HTMLを返す。画面のボタンから別窓を開き「印刷／PDFに保存」を使う。スタンダードは1段、マガジンは解説2段。論理ページごとに改ページし、長文は複数物理ページへ流す（14物理ページ固定ではない）。HTMLエスケープし、外部アセットは読み込まない。

全件未承認草案・正式出力不可。これはブラウザ印刷経由の確認用PDFであり、正式発行PDF・サーバー側PDF生成・ダウンロードAPIではない。ブラウザ/PDF実出力・改ページの視覚検査、本番Clerk/D1・実契約の受入、独立暦照合、原文承認は未完了。図表の正式デザインと版面の調整も継続対象。

検証は `npm test` と `npm run build`。API検査は署名付きローカルJWTと模擬D1を使用する。保存/復元、原文更新後の固定、再保存、メモ保存、改変拒否、権限降格/再昇格、未認証拒否、A4両形式を検査する。
