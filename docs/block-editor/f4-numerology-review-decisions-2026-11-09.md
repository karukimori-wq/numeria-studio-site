# F4 数秘術の担当者判定API

`GET/POST /api/admin/numerology-reviews/:requestId` を追加。Clerk署名検証で得たユーザーIDが `NUMERIA_NUMEROLOGY_REVIEWER_USER_IDS` に含まれる担当者のみ利用できる。同設定が未定義のときは既存の管理者ユーザーID許可リストを使用する。明示的な空文字列で無効化できる。メール・ユーザーID等のブラウザヘッダーで権限を取得できない。許可リストは運用担当者の全体権限であり、依頼者とは別のユーザーの依頼も対象workspace内で参照できる。一般ユーザーへは付与しない。

GETは依頼時点の人物・入力・数値・計算版・入力ハッシュと既存判定を返す。一覧・検索画面は未実装で、依頼番号を指定する。POSTはapprove/return、期待する入力ハッシュ、コメント、証拠URL、確認項目だけを受け付ける。サーバーで承認者ID・判定ID・日時を付け、migration0006の別テーブルへ保存する。

承認ではコア数・氏名規則・期間・比較の4確認項目、HTTPSの証拠参照、コメントを必須とする。URLは参照として保存するだけでサーバーからアクセスしない。依頼ハッシュと現在の計算実装による再計算も検査する。独立検証を実際に行ったことを担当者が明示する操作であり、URLの存在やコードの一致だけで検証完了としない。本番の実在依頼へ今回自動承認は行わない。

判定は依頼ごとに最初の1件を不変保存する。競合する判定・再送・上書きは409。同一入力の再依頼は既存依頼を再利用するため、同一依頼の再審査・承認撤回は現段階ではできない。依頼提出後に鑑定が変わっても判定対象は提出時点の値に固定され、所有者の取得経路は現在の保存入力ハッシュに一致する判定のみを返す。

所有者の「依頼状況を確認」はpending/returned/approvedを扱う。差戻しコメントはtextContentで表示。承認済み情報は現在の鑑定とアダプターで再照合し、画面の確定結果へ渡す。ページ固有の原文・正式図表が未接続のため、14固定ページは引き続き正式発行不可。

テストは実SQLiteで証拠不足・ハッシュ不一致・権限・workspace・数値再計算・承認/差戻し・不変履歴・競合を検査。RS256の実署名/JWKS fixtureを使ってsecureWorker経由の担当者GET/POST、一般ユーザー403、明示無効化、偽装ユーザーヘッダー拒否を確認する。実handler→SQLite→所有者取得→クライアント/DOM→アダプターの往復も検証。

残り：担当者の一覧・確認画面、再審査/撤回設計、実Clerk・ブラウザ/iPhone受入、追加の独立照合、原文・図表・ページ固有証拠、旧本文/AI/PDFとの統一。F4全体は継続中。
