# F4 数秘術の計算スナップショットと照合

## 実装範囲

鑑定のスナップショット生成時に、`numerologyCalculation` を追加する。保存基準日、本人／相手の入力、確認済みの使用氏名と出生時／現在の種別、計算方式の版、コア数、全14ページの計算値と不足理由を同じ下書きへ保存する。既存のD1保存・再開経路を使う。

これは計算済み下書きのチェックポイントであり、`status: calculated` と `verificationState: review-required` を付ける。正式な `confirmed`、`validationEvidence`、`pageAvailability` は生成しない。入力不足のコアはnullで保存し、日付だけの結果は維持する。数秘術以外へ切り替えたスナップショットには数秘チェックポイントを残さない。

同じ入力・計算版での生成は決定的で、時刻やランダムIDを混ぜない。保存ACKと現在のスナップショット比較を維持し、送信済みスナップショットを編集中に書き換えない。読み込み後の下書きスナップショット取得では現在の計算版で再計算する。発行済みReportの不変スナップショットや計算版の移行処理とは別であり、旧版の正式結果を自動移行する機能は未実装。

ピナクルは満年齢に加えて開始日・終了日（排他的）を返す。通常の誕生日は採用仕様74に従う。2月29日の非閏年の応当日、または西暦1〜9999外はnullと `dateBoundaryStatus: unresolved`。2月28日／3月1日や範囲内の日付へ自動補正しない。年齢の境界と数値は保持し、チャレンジへ期間を付けない。

## 数値照合

`test-fixtures/numerology-reference-cases.json` に独立した出典・入力・期待値を固定し、`scripts/verify-numerology-references.mjs` で本番に組み込む計算モジュールを実行する。

- Notion07の数秘6例：8コア＋月運、氏名なし、Y子音、母音のみ、名前の数字分布、ピーク／チャレンジ。元の確認状態は保持し、今回の実行結果と混同しない。
- 外部公開例5件：ライフパス3例、ピナクル4値の例、2026年の個人年・月の例。
- 実行結果と期待値を `evidence/numerology-reference-run-2026-11-06.json` に記録。全11例が一致。ただし全日付・全氏名の網羅、実ブラウザ・PDFの受入合格、正式公開の承認ではない。

外部資料は次の公開例に範囲を限定する。

- [Numerology.com](https://www.numerology.com/articles/your-numerology-chart/life-path-number-meanings/) の1980-10-22のライフパス5。
- [World Numerology](https://www.worldnumerology.com/do-your-own-reading/) の1990-08-12の3、1983-11-22の9、1949-05-15のピーク11／11／22／1、5月15日生まれの2026年2月の個人年3・個人月5。

World Numerologyには氏名の途中縮約やYの扱いが採用仕様と異なる説明があるため、同資料を氏名計算全体の正解証拠に流用しない。氏名の計算は利用者の採用決定とNotionの手計算例に照合する。顧客データは外部へ送信しない。

## 検証と残り

パッチ済みの実スナップショット関数をVMで実行し、D1実SQLのSQLite検証ではチェックポイントを保存・再開API経由で読み戻す。欠損・入力変更・非数秘への切替・保存ACKの安定性・正式結果として拒否されることも検査する。

F4-02／09は継続中。独立した氏名計算・追加境界の照合、正式結果の承認・版と人物を結ぶアダプター、ページ固有証拠、登録原文・正式図表、旧AI／本文／PDF経路の統一、実ブラウザ確認が必要。今回の照合結果を各鑑定の承認証拠へ自動転用しない。F3 Draft PR #80は保留。
