# 四柱の保存済み計算をページ構成で確認（2026-11-18）

既存の確定結果contractはstatus=confirmedと検証証拠・ページ証拠を要求する。今回の計算チェックポイントはdraftであり、承認済みに変換して正式図表/PDFへ通すことはしない。

保存済み計算を確認できる専用画面を追加する。ブロックエディタの四柱入力の「計算データのページ見本を開く」から、APIが返した利用可能ページ定義に限定して選択する。Free定義5件を渡した場合は5件のみ。全14件の純粋renderer検査はPro相当の定義fixtureで行い、実Proアカウント合格とは区別する。

現在のプリセットの許可済みlayoutId（standard/magazine）を読み取り、計算表/構成数/期間の情報と未承認の解説欄をA4構成で表示。これは正式12図表の代替承認や最終組版/PDFの完成ではなく、保存した各ページの計算の確認である。実際のページ定義のtitle/IDを使い、他占術を混ぜない。

BAZ-01/02は柱、03は天干・地支6/8字の五行構成、04/05は採用固定表の役割/通変星/十二運、06/07/13/14は大運と節年の範囲、08/12は対応柱限定の2名比較、09/10/11は用途ごとの配置を表示。正常0件と入力不足を区別し、欠けた構成数を0で埋めない。元の本文・プリセットは編集しない。

対象者・占術・入力scopeを照合し、draft/schemaとpublicationAllowed=falseを要求する。ブラウザのscope確認はサーバー計算値の独立検証ではない。下書き画面のHTMLを確定resultとして出力へ接続しない。解説文章と正式素材は未承認、正式発行不可の表示を各ページに置く。ネイティブ印刷のCSSでも計算内容を隠し、発行不可の文だけを表示する。既存アプリの正式印刷guardは変更しない。

検証: 14ページ×2レイアウト、Free5定義、保存scope/対象者差分、confirmed/publication偽装、正常0件・不足、HTML escape、構成数欠損をNodeで検査。実ブラウザのプラン・レイアウト・スクリーンショットは別途記録する。

レビューで見つかった比較配列欠損時の偽0件を修正。実際の空配列だけを正常0件とし、欠損/null/objectは不足を表示する。配置欠損も明示する。全npm test/build・diffチェック、修正後の二軸レビュー成功。実rendererとoverlayをVMで実行し、ページ切替・一重起動・listener解放・Tab循環・Escapeによる下位エディタ誤閉鎖防止・元のボタンへのfocus復帰を確認した。
