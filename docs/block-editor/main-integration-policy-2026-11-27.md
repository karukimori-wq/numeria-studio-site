# main反映後に利用者確認を行う方針

2026-11-27、利用者から「開発を進めて下さい。確認はmainにPushしてから私が行うので考慮しなくても良いです」と指示された。これ以降、利用者確認待ちや実Pro検証アカウントの未用意をmain反映の前提条件にしない。実装・自動検査・コードレビューを行い、mainへ反映した状態で利用者確認を受ける。

今回の統合基点はmain 5d002e2818e2385f896f3a7243024c98488ddda7、開発コードは7c54dc67ed1afe84e61d17ec80ad1b1b25bc23e4まで。F1–F5の共通図表・九星と四柱の計算草案・入力保存復元・認証とプラン制限の修正・A4検査と証拠を統合する。利用者本文を他鑑定へ混入させない修正、再開済みSessionの同じIDへの保存、正式IDの復元も含む。

main反映は全85ページの正式受入や原文・素材の専門承認を意味しない。未確認の項目は未確認のまま記録し、Notion「私の確認」や承認storeを自動で承認済みにしない。既存の正式発行条件を維持して、未承認の計算・原文・図表は草案として表示する。残る計算経路統一、他占術の接続、正式PDF等は後続開発として継続する。

新しいDBマイグレーションは追加しない。検証環境専用の追加管理者IDを本番へ転用しない。既存のmain用Cloudflare Production workflowでテスト・ビルド・配信・公開サイトの検査を行う。main反映後の配信結果はGitHub ActionsとPR #99に記録する。

最終レビューで九星の保存基準日時ロックが直前snapshotの占術フラグに依存する欠陥を発見。入力またはcheckpoint sourceの固定日時から、占術フラグと独立して保護するよう修正した。SQLite実APIで「別占術を経由→日時変更／入力削除」を修正前は受理、修正後は409と保存値不変、元日時のまま本文更新は201を確認。両軸再レビューの必須指摘は解消した。PDF証拠はbinary属性のみ追加し、内容を変更していない。
