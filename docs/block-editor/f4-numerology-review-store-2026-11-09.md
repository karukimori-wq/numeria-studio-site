# F4 数秘術の検証依頼保存

`GET/POST /api/appraisals/:id/numerology-review` を追加。Clerkの検証済み本人性を必須とし、既存の鑑定読込APIによる所有者・workspace・履歴権限制御を経由する。ブラウザのユーザーID・管理者メールを本人確認に使わない。取得結果の所有者と検証済み本人が一致することも検査する。

POSTはexpectedDraftVersionだけを受け付け、サーバー保存済みスナップショットから計算版・人物・使用氏名・基準日・計算値を取得する。現在の計算との一致を検査し、依頼IDと提出日時をサーバーで付ける。入力ハッシュはSHA-256。同じworkspace・本人・鑑定・入力の依頼を重複保存しない。依頼は履歴として保持し、GETは現在の保存入力と一致する依頼だけを返す。

新規migration0005は独立した依頼テーブルのみを追加する。依頼状態はpending、approvalは常にnull。承認済みの発行経路は今回作らず、依頼の保存・提出を独立検証完了と扱わない。POST中に下書きが変更された場合も保存した依頼は読込時点の入力に固定され、現在入力が変わるとGETでは一致しなくなる。

テストは実SQLiteで保存・再取得・重複・本人/workspace分離・古い版・改変・不正承認フィールドを検査。secureWorkerへの偽装ヘッダーはobserveモードでも401となることを確認。

画面からの依頼操作、実JWTを伴う取得成功の統合確認、独立検証担当者の権限・承認発行・署名/認証・承認履歴の取得とアダプター接続は後続。F4全体は継続中であり、正式発行は開放しない。
