# F4-02 ローマ字氏名の確認・保存

2026-11-03。採用86項目の4・5・7・13・16に基づく数秘術の氏名入力を実装。

## 実装

- 鑑定書ビルダーの設定に、本人／相手のローマ字氏名確認欄を追加。出生時の氏名を初期選択とし、現在の氏名と別々に入力・保存する。相手の入力欄は相性オプション有効時だけ表示。
- 入力と確認は別操作。全角英字・大小文字・空白等を正規化し、A〜Z以外や空欄は確認できない。旧birthNameが入力済みでも確認済みと推定しない。
- 確認は正規化した氏名と、その時点の本人／相手の表示名・生年月日・旧出生名に結び付ける。氏名編集時は該当欄の確認を解除。人物情報が変わった場合も再確認が必要。
- 選択した氏名の種類と確認済みの計算用氏名をページデータに記録し、計算プレビューへ表示する。日付依存の結果は氏名が未確認でも維持する。
- `numerologyNameInputs` をReactの鑑定スナップショットへ追加。既存のD1下書き保存・読込経路を使用し、保存済み鑑定の再開で復元、新規開始ではリセットする。別のlocalStorage保存先は作らない。
- 「鑑定の下書きを保存」は既存の鑑定保存処理を呼ぶ。フォーマット保存とは別操作。保存ACKと失敗を区別し、保存中に氏名が変わったら再保存を案内する。送信済みスナップショットを後から書き換えない。

## 検証

- 純粋な入力更新・確認・種類切替、無効文字、人物変更、旧データ、コピー後の復元、計算ページへの接続を検査。
- 実際の旧バンドルに本番パッチを当て、スナップショット／更新／復元／新規リセットの処理をVMで実行。
- フォームの入力・確認・保存ACK・保存中変更・保存エラーをDOM境界のfixtureで実行。
- Workerの実SQLをSQLiteで実行し、出生名／現在名と確認情報をD1へ保存し、読込APIが同じデータを返すことを検査。
- 全体テスト・本番ビルドで構文・配信ファイル・既存保存処理の回帰を確認。

## 残り

氏名の「確認済み」は入力確認であり、数秘計算の独立照合済み・正式な鑑定結果確定・本文承認ではない。従来の数秘術本文・AI下書き・PDF生成器はまだ旧計算器を使うため、今回の氏名選択をそれらへ渡さない。対象はF4計算プレビューと鑑定スナップショット。

独立した計算正解との照合、確定結果アダプターとページ単位証拠、登録原文・F3正式図表の接続、ピークの実年月日境界、実ブラウザ・iPhone/PDF確認は継続。F4数秘術全体は未完了。F3 Draft PR #80は保留のまま。
