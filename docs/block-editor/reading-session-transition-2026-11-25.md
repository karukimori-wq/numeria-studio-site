# 最近の鑑定の復元と個人別入力の分離

数秘術の実画面検証中、ダッシュボードの「最近の鑑定」を選んでも保存内容を復元せず、顧客だけを選んだ新規入力を開く不具合を発見。前に開いていた四柱推命の占術・本文・相手情報等が残り得た。再現中に保存は行っていない。

保存snapshot IDがある行は既存の認証付きSession詳細routeへ進み、サーバーから最新版snapshotとdraftVersionを取得して復元する。古いローカルsnapshotだけで再開しない。取得失敗は既存routeのエラー画面で止める。snapshotがない行は表示行の占術・メニューで新規開始し、前人の本文、導入、助言、自由項目、相手、出生入力、占術別コメント、Session IDをクリアする。表示設定は保持する。

既存の保存復元handlerも補強した。出生時刻・出生地の空文字を無視せず、欠損した個人文字列は空文字へ正規化。コメントを現在stateへmergeせず、初期の空文字shapeへ保存値を重ねる。旧snapshotの欠損をReactのundefined入力へ流さず、比較フラグと自由項目にも既定値を設定する。保存済み本文・部分コメントは保持する。

実元bundleへ本番patchを当て、実クリックhandlerと実復元handlerをVM実行。saved/no-snapshot経路、空/欠損出生値、部分コメント、導入/助言/相手の欠損、保存済本文保持、新規Session ID解除を検査。全npm test/buildとgit diff --check成功。仕様軸レビューの2指摘、規約軸の空shape・欠損文字列指摘を修正し、再レビューで必須指摘なし。

検証配信: commit ab68a15、Actions run45585897141。認証付きChromeでの配信後確認はこの記録の次項へ追記する。main・本番Worker・DB schema・正式承認は変更しない。85ページの正式受入、実Pro受入へは加算しない。

追加調査で、保存失敗の理由が共通statusに隠れる問題も修正。既存APIの4種類のerrorCodeだけを固定の日本語案内へ対応付け、未知コードやconstructor等は共通表示へ戻す。rawサーバー本文は表示しない。commit374415c／run45588091961は成功し、実画面にFree未完了1件制限を表示した。ただし一覧は同じ1件のみだったため、別案件があるとは断定しない。

Session読み取り応答のwithRestorableSnapshotにはsnapshot.idの正規化がなく、旧snapshotの欠損／別ローカルIDで再保存が新規IDとして扱われ得る。認証済みSessionレコードのidを応答snapshotへ設定する修正を追加（commit9774364）。実API fixtureで欠損と旧IDの2ケースを取得→同じFree下書きへ期待版付きで再保存し201を確認。本文・計算checkpoint・保存制限・DBschemaは保持する。両レビュー軸の追加指摘なし。

ID正規化後も実画面の保存はFree上限で停止。トップ保存ボタンが呼ぶCiを追うと、再開済みIDのDnを見ずに毎回`${l}-${Date.now()}`を採番していた。これが今回の再保存失敗の直接原因。Dnがある場合だけ、既存ID・期待保存版・完全snapshot・ACK処理を持つIiへ委譲する修正を追加（commit7c6011b）。Dnがない新規開始は元のCiを維持。実CiのVMで1回だけ委譲されることと、全test/build、両軸再レビューを確認した。
