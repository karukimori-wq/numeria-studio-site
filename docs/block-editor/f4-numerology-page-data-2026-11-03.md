# F4-02 数秘術14ページの計算プレビュー

2026-11-03。前回の計算基盤に、採用86項目の73〜75で定義されたピナクル・チャレンジを追加し、全14ページの必要値・不足値を `src/numerology-page-data.js` に実装した。

## 接続した範囲

- NUM-01〜04・09〜11: 指定されたコア数の組合せ。NUM-04はライフパスとデスティニーからマチュリティへの計算依存だけを記録。
- NUM-05: 氏名の数字分布・未出現・最多同率。
- NUM-06・14: 保存された鑑定基準日に基づく9年周期・対象月。再閲覧時に今日の日付へ置換しない。
- NUM-07: 8コアを由来別に分類。採用決定77に従い、台帳名を「あなたの数秘マップ」に改称。生命の樹を採用しない。
- NUM-08・12: 本人／相手のライフパスを中心に、双方算出できる補足項目だけを比較。点数化しない。NUM-12には家族関係も必要。
- NUM-13: ピナクル4段階の数・満年齢境界（誕生日切替）と、期間を持たないチャレンジ4項目。チャレンジ0は有効、第3は生涯の主要課題。

必要値が不足するページは `input-incomplete` と不足キーを返し、データをnullにする。計算済みページも `calculated` であり、正式な `confirmed` や掲載許可の証拠を生成しない。正式参照台帳の `unconnected` は維持する。

## 本番画面との接続

ブロックエディタの設定欄に「数秘術の計算プレビュー」を追加。既存の `NumeriaNavigation.getReadingSnapshot()` から、現在開いている数秘術鑑定の生年月日・保存基準日・相手の生年月日・家族関係を読む。相手比較は鑑定の相性オプションが有効な場合だけ。既存のプラン別ページ定義で表示範囲を絞る。プレビューは編集・印刷・保存する鑑定本文には挿入しない。

旧スナップショットにはローマ字氏名の明示確認がないため、出生名の入力済み状態を確認済みと推定しない。現時点の実画面では氏名依存ページは不足表示になる。純粋な計算接続関数は、確認済み氏名を明示した入力に対応する。不正な氏名でも日付だけの結果は維持する。

## 検証

`scripts/verify-numerology-page-data.mjs` で14ページ、入力欠損、2名比較、ピークのマスター保持、LP8の28／37／46歳境界、チャレンジ0と期間なし、基準日固定、プラン絞り込み、文字列のエスケープ、実ランタイムのプレビュー挿入部分を検証する。従来の全体テスト・本番ビルドも実施する。
