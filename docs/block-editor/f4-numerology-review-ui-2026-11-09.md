# F4 数秘術の検証依頼UI

鑑定書ビルダー→設定→数秘術の計算プレビューに「検証を依頼」「依頼状況を確認」を追加。自動送信や外部への通知は行わず、既存の認証付き検証依頼APIを明示操作で呼ぶ。

最初に保存済み鑑定を取得し、Session ID、人物、使用氏名、相性、基準日、計算版、計算チェックポイントが現在の計算入力と一致することを確認する。未保存の計算入力がある場合は下書き保存を案内する。本文・テーマなど計算対象外の編集は照合対象外。

POSTは保存済み鑑定から取得したexpectedDraftVersionのみを送る。サーバーは独立して認証・所有者・保存済み入力・版を再検査する。依頼状態はpendingだけを受け取り、承認済みとは表示しない。GETで未依頼、POSTで保存応答が不完全、401/403/409/422、通信失敗、JSON破損を区別する。サーバー応答の文言はそのままUIへ反映しない。

通信中は両ボタンを無効化。認証ヘッダー取得後も現在入力を再照合し、入力変更や鑑定切替後に古い結果を現在の状態として表示しない。変更が送信後に発生した場合、依頼は送信時点の保存内容を対象に履歴へ残り得るが、現在画面では再保存を案内する。

検証は本番クライアント関数のfixture実行と、既存Worker handler・実SQLiteを経由するクライアント→保存→重複再利用の往復。UIボタンの二重操作・無効化・復帰・遅延応答・入力変更も検査する。実JWTを使ったログイン済みブラウザ/iPhoneでの受入は未実施。

承認発行・発行元認証・検証担当者の操作・承認履歴と確定結果への接続、登録解説・正式図表・PDFは後続。F4は継続中。
